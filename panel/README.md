# SMS-рассылка через Android-телефон

Веб-панель на Mac управляет рассылкой, а SMS физически уходят с SIM-карты
вашего Android-телефона по локальной сети.

```
Mac: панель + база (SQLite)  ──HTTP──▶  Android: SMS Gateway  ──▶  SIM  ──▶  SMS
                          по USB-кабелю или Wi-Fi
```

## Почему именно так

Android не позволяет отправлять SMS с компьютера напрямую: у `adb` нет
разрешения `SEND_SMS`. Поэтому на телефоне работает приложение-шлюз с этим
разрешением, а панель обращается к его локальному HTTP API.

## Установка

### 1. Телефон

1. Установите **SMS Gateway for Android** — APK со страницы релизов:
   https://github.com/capcom6/android-sms-gateway/releases
2. Выдайте разрешение **Отправка SMS**.
3. Включите переключатель **Local Server** → нажмите кнопку **Offline**.
4. Запишите показанные **логин и пароль**.
5. Отключите оптимизацию батареи для приложения: иначе Android усыпит шлюз
   посреди рассылки. *Настройки → Приложения → SMS Gateway → Батарея → Без
   ограничений.*

### 2. Mac

```bash
cd ~/Desktop/рассылка && ./run.sh
```

Первый запуск создаст `.venv` и поставит зависимости. Откроется **нативное
окно приложения** — движок системный (WKWebView на macOS, WebView2 на
Windows), браузер не нужен.

Нужен старый веб-режим в браузере (удобно для отладки):

```bash
.venv/bin/python app.py
```

Порт подбирается свободный начиная с 5001 (5000 на macOS занят «Приёмником
AirPlay»), поэтому окно и веб-режим могут работать одновременно.

Дальше: **Настройки** → впишите логин и пароль с телефона → выберите способ
подключения (ниже) → **Проверить связь** → **Отправить тест** себе.

## Способ подключения

Панель умеет работать двумя способами, переключатель — в Настройках.

### По кабелю (рекомендуется)

Адрес не меняется никогда, Wi-Fi не нужен вовсе — телефон может сидеть на
мобильном интернете и попутно заряжается во время рассылки. `adb` пробрасывает
порт шлюза с телефона на `127.0.0.1` ноутбука:

```
Mac: панель → 127.0.0.1:18080 ──USB (adb forward)──▶ телефон: 8080 → SIM
```

Подготовка:

1. Один раз поставить Android Platform Tools:

   ```bash
   brew install --cask android-platform-tools
   ```

2. На телефоне открыть режим разработчика: **Настройки → О телефоне** → семь раз
   нажать **Номер сборки**.
3. **Настройки → Для разработчиков** → включить **Отладка по USB**.
4. Подключить кабель, на экране телефона нажать **Разрешить отладку по USB**.
5. В панели: способ подключения **USB-кабель** → **Подключить по USB**.

Кнопка **«Что видит adb»** показывает путь к adb, список подключённых телефонов
с их состоянием и действующие пробросы портов — по ней сразу понятно, на каком
шаге застряло.

Проброс не переживает извлечение кабеля и перезагрузку телефона, поэтому панель
поднимает его сама: перед запуском кампании и при обрыве связи посреди рассылки.

### По Wi-Fi

Телефон и Mac должны быть в **одной сети Wi-Fi**. Адрес берётся из приложения
или кнопкой «Найти телефон». Минус способа: в сети с DHCP адрес телефона
периодически меняется, и сохранённый IP перестаёт работать.

### Кнопка «Найти телефон»

В обычной сети адрес телефона выдаёт DHCP, и после переподключения он меняется —
сохранённый IP перестаёт работать. Кнопка сканирует вашу подсеть и опознаёт шлюз
по ответу `GET /health`: он отдаёт JSON с `releaseId`, `version` и проверками
вида `battery:level`. Найденное устройство показывается с версией и уровнем
заряда — легко убедиться, что это ваш телефон.

**Пароль при сканировании не отправляется никуда.** Чужие устройства с тем же
открытым портом (принтеры, камеры, панели) в кандидаты не попадают: они
перечисляются отдельно, с пометкой, что шлюзом не являются. Пароль уходит только
на тот адрес, который вы выбрали кнопкой «Использовать».

## Как пользоваться

1. **Контакты → Загрузить файл.** CSV или Excel. Первая строка — заголовки;
   обязательна только колонка с телефоном. Кодировка (UTF-8/Windows-1251) и
   разделитель определяются автоматически, колонки угадываются, но их можно
   поправить вручную.

   ```csv
   телефон;имя;город;согласие
   8 (900) 111-22-33;Иван;Москва;да
   +7 900 222 33 44;Мария;Казань;да
   ```

   Номера приводятся к `+7…`, дубликаты объединяются, невалидные строки
   отбраковываются со списком причин, номера из стоп-листа не импортируются.

2. **Новая рассылка.** Текст с переменными из колонок файла:
   `Здравствуйте, {имя}! Ждём вас в {город}. Отписка: СТОП`
   Справа — живой предпросмотр на реальных контактах, счётчик символов и
   **число SMS-сегментов**.

3. **Запустить.** Перед стартом панель сама проверяет связь со шлюзом.
   На странице кампании — прогресс, журнал по каждому номеру, пауза,
   остановка, повтор неудачных и выгрузка отчёта в CSV.

### Кириллица дороже

| Алфавит | 1 SMS | В составном |
|---|---|---|
| Латиница (GSM-7) | 160 симв. | 153 |
| Кириллица (UCS-2) | **70 симв.** | 67 |

Одна русская буква в тексте переводит всё сообщение в UCS-2. Панель считает
сегменты и показывает итог до запуска — смотрите на это число, оно и есть
стоимость рассылки.

## Ограничения, о которых лучше знать заранее

- **Android** без подтверждения пользователя пропускает около **30 SMS за 30
  минут** на приложение. Панель по умолчанию держит паузу 4 сек ± 2 сек и
  лимит 100 SMS/час — эти значения настраиваются на каждую кампанию.
- **Оператор** может заблокировать SIM за массовую рассылку с обычного номера.
  Реалистичный потолок обычного тарифа — сотни SMS в сутки, а не десятки тысяч.
  Для больших объёмов нужен официальный SMS-агрегатор с буквенным именем
  отправителя.
- **Закон.** Реклама по SMS без предварительного согласия абонента —
  нарушение ст. 18 ФЗ «О рекламе», штраф на юрлицо до 500 тыс. руб.
  Поэтому в панели есть поле «согласие» у контакта, фильтр «только с
  согласием» и стоп-лист. **Добавляйте в текст способ отписки** и вносите
  ответивших «СТОП» в стоп-лист.

## Устройство проекта

```
app.py                  веб-панель (маршруты Flask)
smsblast/
  config.py             настройки, пути, значения по умолчанию
  db.py                 схема SQLite и запросы
  discovery.py          поиск телефона в локальной сети по подписи /health
  gateway.py            HTTP-клиент шлюза на телефоне, разбор сетевых ошибок
  importer.py           чтение CSV/XLSX, разметка колонок
  phones.py             нормализация номеров, подсчёт SMS-сегментов
  sender.py             фоновый воркер: очередь, темп, повторы, статусы
  templating.py         подстановка {переменных}
  usb.py                подключение по кабелю через adb forward
desktop.py              запуск в нативном окне (оболочка приложения)
tests/                  автотесты: test_core.py и test_connection.py
templates/, static/     интерфейс
smsblast.db             база (создаётся при первом запуске)
```

Данные лежат в `smsblast.db` рядом с проектом. Там же пароль от шлюза — файл
уже добавлен в `.gitignore`.

### Надёжность отправки

- Каждому SMS присваивается собственный `id` — повторная попытка не создаёт
  дубль на телефоне.
- Обрыв связи: до 3 попыток с нарастающей паузой; 5 ошибок подряд ставят
  кампанию на паузу, чтобы не сжечь очередь, пока телефон недоступен.
- Неверный логин или отказ шлюза останавливают кампанию сразу.
- Стоп-лист проверяется ещё раз непосредственно перед каждой отправкой.
- Одновременно идёт только одна кампания — SIM-карта одна.

## Если что-то не работает

Панель различает сетевые сбои по состоянию TCP-соединения, а не по тексту
исключения, поэтому сообщение прямо указывает, что чинить:

| Сообщение | Что произошло | Что делать |
|---|---|---|
| «телефон не отвечает по адресу X» / «устройства X нет в сети» | соединение не установилось: адреса в сети нет | у телефона сменился IP, он на мобильном интернете или в другой сети — нажмите **Найти телефон** |
| «порт 8080 закрыт — телефон в сети, но шлюз не слушает» | устройство отвечает, но порт закрыт | включите **Local Server** в приложении и нажмите **Offline** |
| «шлюз принял соединение, но не ответил вовремя» | соединение есть, ответа нет | телефон усыплён — разбудите экран, отключите оптимизацию батареи |
| «шлюз отверг логин/пароль» | 401 от шлюза | пароль меняется при перезапуске Local Server — перепишите заново |
| «логин или пароль содержит нелатинские символы» | кириллица в поле | промах раскладки: Basic-авторизация допускает только latin-1 |
| «адрес не разрешается» | в поле адреса не IP | впишите адрес вида `192.168.1.50` |
| Рассылка встала посреди базы | Android усыпил приложение | отключите оптимизацию батареи |
| Статус остаётся `sent`, не `delivered` | оператор не прислал отчёт о доставке | это нормально, не все операторы их отдают |

Для подключения по кабелю:

| Сообщение | Что делать |
|---|---|
| «adb не установлен» | `brew install --cask android-platform-tools` |
| «телефон по USB не найден» | подключить кабель и включить «Отладка по USB» в разделе «Для разработчиков» |
| «телефон подключён, но не готов: … (unauthorized)» | на экране телефона нажать «Разрешить отладку по USB» |
| «… (offline)» | переподключить кабель, разблокировать телефон |
| «подключено несколько устройств» | оставить в USB только телефон со шлюзом |
| «локальный порт занят» | сменить локальный порт в настройках (по умолчанию 18080) |
| «порт … на Mac никто не слушает» | проброс отвалился — нажать «Подключить по USB» |

Полезная деталь при отладке вручную: **таймаут** и **connection refused** —
разные поломки. Таймаут означает, что устройства нет в сети (ARP не
разрешается); refused — что телефон на месте, но шлюз не запущен.

## Что можно добавить дальше

- Автоматическая отписка: приём входящих SMS «СТОП» через вебхук шлюза
  (шлюз умеет `sms:received`) и внесение номера в стоп-лист без участия
  человека.
- Отправка по расписанию (шлюз поддерживает поле `scheduleAt`).
- Подтягивание контактов из Bitrix24 вместо файла.
