# Сборка автономного приложения

Здесь лежит **только сборочная обвязка**. Исходники копируются из рабочего
проекта `~/Desktop/рассылка` в момент сборки — рабочее приложение не
изменяется, и второй копии кода, которую пришлось бы править дважды, не
появляется.

```
~/Desktop/рассылка          рабочий проект (не трогаем)
~/Desktop/рассылка-сборка   эта папка: скрипты сборки
~/Applications/SMS-рассылка.app   результат
```

## macOS

```bash
cd ~/Desktop/рассылка-сборка && ./build.sh
```

Получится `~/Applications/SMS-рассылка.app` — 13 МБ, запускается двойным
щелчком, Python и `.venv` не нужны. Панель откроется в браузере сама.

Собрать можно и из другой папки с проектом:

```bash
./build.sh /путь/к/папке/рассылка
```

### Почему результат не в этой папке

Ваш `~/Desktop` — домен файл-провайдера **iCloud Drive**. Он навешивает на
файлы `com.apple.FinderInfo`, а `codesign` отказывается подписывать бандл с
такими «посторонними данными»:

```
resource fork, Finder information, or similar detritus not allowed
```

На Apple Silicon неподписанный бинарник **не запускается вовсе**, поэтому
сборка складывает результат в `~/Applications` (вне синхронизации), чистит
расширенные атрибуты и подписывает локальной ad-hoc подписью. Скрипт проверяет
подпись сам и предупредит, если она не прошла.

### Подпись и передача на другой Mac

Подпись **ad-hoc** — своя, без сертификата разработчика. На этом Mac приложение
запускается без предупреждений (файл не помечен карантином). Если передать
`.app` на другой Mac, macOS его заблокирует: получателю нужно один раз нажать
правой кнопкой → **Открыть**. Чтобы приложение открывалось у всех штатно, нужны
платный Apple Developer ID и нотаризация — это отдельная история.

## Windows

### Что отличается в Windows-варианте

Код один, но несколько мест работают по-разному — иначе на Windows они просто
не работали бы:

| Что | На macOS | На Windows |
|---|---|---|
| Определение подсетей для «Найти телефон» | `ifconfig` | PowerShell `Get-NetIPAddress` (JSON, не зависит от языка системы); запасной вариант — свой адрес через сокет и /24 |
| Поиск `adb` | homebrew, Android Studio | `C:\platform-tools`, `%LOCALAPPDATA%\Android\Sdk`, scoop, chocolatey |
| Подсказка при отсутствии `adb` | `brew install --cask android-platform-tools` | ссылка на Android Platform Tools и указание добавить в `PATH` |
| Движок окна | WKWebView (в системе) | WebView2 (есть в Win11 и большинстве Win10) |
| Консоль | не показывается | `.exe` собирается оконным, вывод идёт в `app.log` рядом с базой |

Виртуальные адаптеры Hyper-V, WSL, VirtualBox и VMware из сканирования
исключаются — телефона там нет, а перебор их подсетей только тратит время.

Если WebView2 в системе не окажется, приложение покажет окно с сообщением и
ссылкой на установку, а панель останется доступна в браузере.

**Собрать `.exe` на macOS нельзя.** PyInstaller не умеет кросс-компиляцию: он
упаковывает интерпретатор и библиотеки той платформы, на которой запущен.
Варианта два.

### 1. На Windows-машине

Скопируйте на Windows папку проекта и эту папку, поставьте Python 3 и
запустите:

```
build-windows.bat "C:\путь\к\папке\рассылка"
```

Если рядом с `.bat` уже лежит папка `src` (её создаёт `build.sh` на Mac),
аргумент не нужен — сборка возьмёт исходники из неё.

Результат: `dist\smsblast.exe` — один файл, ничего дополнительно ставить не
нужно.

### 2. Через GitHub Actions

`.github/workflows/build-windows.yml` собирает `.exe` на Windows-раннере и
отдаёт его артефактом. Нужно положить проект и эту папку в один репозиторий и
запустить workflow вручную (**Actions → Сборка Windows .exe → Run workflow**)
или создать тег `v*`. Workflow заодно проверяет, что собранный `.exe`
поднимается и панель отвечает `200`.

## Что важно знать о собранном приложении

**Где данные.** База, загруженные файлы и отчёты лежат не внутри приложения
(в бандл macOS писать нельзя), а в папке пользователя:

- macOS: `~/Library/Application Support/SMS-рассылка`
- Windows: `%APPDATA%\SMS-рассылка`

Путь печатается при запуске. Собранная версия и версия из исходников
используют **разные базы** — это разные наборы контактов и кампаний.

**Порт подбирается свободный.** Если панель из исходников уже занимает 5001,
собранная поднимется на 5002 и напишет об этом — версии не конфликтуют.

**Пароль от шлюза в сборку не попадает.** Копируются только `app.py`,
`smsblast/`, `templates/`, `static/`. Файлы `*.db` и `.env` исключены, и сборка
падает с ошибкой, если они всё же оказались в `src/` — проверка есть в обоих
скриптах.

**Для режима USB нужен `adb`** — он не встраивается в сборку, это внешняя
программа:

```bash
brew install --cask android-platform-tools
```

На Windows — Android Platform Tools от Google, `adb.exe` должен быть в `PATH`.
Если `adb` не найден, панель скажет об этом прямо, а Wi-Fi-режим будет работать
как обычно.

## Пересборка после правок

`build.sh` каждый раз копирует исходники заново, поэтому после изменений в
`~/Desktop/рассылка` достаточно снова запустить:

```bash
./build.sh
```

Окружение сборки (`.venv-build`) переиспользуется — повторная сборка занимает
около 9 секунд.

## Файлы

```

smsblast.spec         конфигурация PyInstaller (macOS — .app, Windows — один .exe)
build.sh              сборка на macOS
build-windows.bat     сборка на Windows
.github/workflows/    сборка .exe в GitHub Actions
src/                  копия исходников, создаётся при сборке
.venv-build/          окружение сборки с PyInstaller
```
